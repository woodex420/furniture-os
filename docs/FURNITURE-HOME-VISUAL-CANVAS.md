# Furniture home visual canvas — limited hero slice

Site Overview now optionally embeds the **actual Reimagin homepage** for selecting and previewing the first slide's title, subtitle and button. Click one of those elements to focus its admin input, or use the keyboard-accessible toolbar buttons to select without losing keyboard focus. The button destination is edited in the form; navigation is blocked in the canvas. The Background toolbar button focuses the image selector, which offers five existing Reimagin hero images. Changing it previews the chosen background immediately; it does not upload media. Typing updates that canvas immediately, without changing saved content. Fit, Mobile (375px), Tablet (768px), and Desktop (1280px) controls change the actual iframe viewport without reloading or saving the draft; fixed widths may require horizontal scrolling. These are viewport previews, not device emulation or separate responsive content settings. The selected title or subtitle can also be moved above or below the other with the toolbar arrows. The form includes an equivalent text-order select that works without JavaScript. This is a constrained two-item reorder, not drag-and-drop or arbitrary positioning. **Update storefront preview** is still the authenticated, CSRF-protected save; save creates a revision containing text, order, button and background, and history can restore it. This slice does not implement free-form movement, delete, connecting uploaded media to the canvas, page creation, other slides, or the full visual page builder. The API and normal storefront use the saved order, button and background; only the first slide changes. Button destinations are constrained to root-relative ASCII paths and query strings, without spaces, backslashes, percent escapes or external URLs. This prevents an editor-entered external link or script URL, but does not check that a destination route exists. Invalid in-progress paths fall back to the original button destination in the canvas until corrected.

An independent experimental private media upload/list is described in `FURNITURE-PRIVATE-MEDIA-PREVIEW.md`; its uploads cannot yet be selected here or published.

## Configuration and boundary

- `FURNITURE_HOME_EDITOR_ENABLED` remains false by default. `FURNITURE_STOREFRONT_CANVAS_URL` is an optional explicitly configured **origin only** (no path, credentials, query or fragment); HTTPS is required except localhost/127.0.0.1 in local/test environments. If absent/invalid, the existing form and history work without a canvas. Configure the appropriate storefront preview origin on the trusted server; never send a sandbox localhost URL to the user's browser.
- The canvas must use a different browser origin from the admin; same-origin framing is refused because scripts in an `allow-scripts`/`allow-same-origin` frame could otherwise access the parent. The admin uses an iframe with a restricted sandbox and no-referrer policy. Its messages target only the configured storefront origin, and incoming events must match both that origin and the frame's `contentWindow`. The storefront accepts preview messages only in explicitly requested embedded canvas mode, from its actual parent and the stated parent origin. The parent origin in the URL is **not authentication**: this protocol only changes temporary pixels in that particular frame and never performs a write, grants admin access or sends credentials. Text is rendered by React, not inserted as HTML.
- The canvas is pinned to the first slide, and ordinary navigation within it is blocked. Its toolbar is labelled UNSAVED CANVAS. A failed/unreachable frame displays a status while preserving the form. JavaScript is required for the canvas, not for form submission. The real public storefront outside this mode has no selection toolbar.
- The Arena preview is configured for port 5174; port 5176 remains a synthetic admin with prefilled demo sign-in. The iframe requires both preview origins to be reachable and permitted by the browser/proxy. Local nested cross-site HTTPS browser testing passed; the actual Arena-hosted browser and frame headers were not independently accessible from the sandbox. If blocked, use the existing form and storefront preview separately and report the status shown.

## Data migration

Migration `2026_11_07_000000_add_home_hero_text_order` adds nullable order columns to the current home row and revision snapshots without rewriting existing records. Null represents the original title-first layout. Older save clients omitting the order preserve the current value. Rolling the migration back drops both order columns and **loses saved ordering**, though text and revisions remain; back up the database before rollback or deployment. Restore app code and schema together. This was tested on isolated SQLite only, not production MySQL.

Migration `2026_11_08_000000_add_home_hero_button` adds nullable button text and destination columns to current content and snapshots. Null preserves the original Shop Now button, while omitted fields from older clients preserve the saved values. Rolling back loses saved button values from both tables, so back up before rollback or deployment and restore app code and schema together. Existing data migration was tested only on synthetic SQLite.

Migration `2026_11_09_000000_add_home_hero_image` adds nullable image identifiers to current content and revisions. Null means the original workspace image; older clients that omit the field preserve the selected image. Only five stable identifiers are accepted, not arbitrary URLs or uploads. Images remain decorative as in the original component. Rolling back removes saved image choices from both tables; back up before rollback or deployment and restore app code and schema together. Tested on synthetic SQLite, not production MySQL.
