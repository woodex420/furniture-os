# Vercel design preview (not production)

The Vercel `furniture-os` project was found building the repository root with `npm run build`, which emits `apps/dashboard/dist`; Vercel's default expected root `dist` and preview deployments failed with `STATIC_BUILD_NO_OUT_DIR`. Root `vercel.json` selects the actual dashboard output, with a locked install command, noindex response header and a preview-only ignore command. The dashboard also emits a noindex meta tag and disallow-all robots file. Those are crawler instructions, **not access control**.

The branch preview deployment for commit `6091f1c` reached READY, and an anonymous request was redirected to Vercel login. The connector's file-tree endpoint returned 404 for this deployment too, so deployed file contents and an authenticated browser session were not independently inspected. The fix is limited to this branch; it did not replace the older production deployment.

This is only the standalone React **design preview** with sample records. It has no Laravel server, Furniture database, owner authentication, builder persistence, hosting validation or production commerce. Do not enter real customer or business data. The Vercel project was observed with deployment protection (`all_except_custom_domains`); maintain it and verify protection for every alias/custom domain before sharing. Do not attach a public custom domain to this preview. Server-side protection, not noindex, is necessary. Google Fonts remain an external browser request in the standalone dashboard.

The Vercel ignore command exits nonzero only for Vercel's `preview` environment; production, custom environments, and missing/unrecognized values are skipped. This protects future builds using this configuration; it does not alter or remove an existing deployment, stop manual dashboard overrides, or constitute a production release policy by itself. Project settings, Git settings and deployment protection must still be reviewed independently. The Vercel project reported an older main-branch production target (initial repository commit), not the current Laravel application. Its served output and access were not verified; `list_deployment_files` returned 404. It was not modified, promoted or deleted.

The independent Hostinger staging/production plan and its NO-GO status are unchanged. A successful Vercel static build does not validate PHP, MySQL, immediate crawler-visible publication, access controls, or Hostinger deployment. Repository tests validate the build output contents, crawler instructions and fail-closed environment guard; actual Vercel configuration and HTTP behavior need separate verification.
