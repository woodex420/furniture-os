# First hero uploaded image — preview integration

The experimental Furniture media library is connected to the first homepage slide. In Site Overview, choose an uploaded background (the latest 100 are listed, plus the current selection) or choose a bundled image. The canvas previews the choice without saving it; Save creates a revision and makes that selected image public on the connected storefront preview. Restoring an image-bearing revision also makes its image public. This is **not** a general media picker, upload-to-publish workflow for other pages, or production deployment.

## Privacy and publication

Uploads are initially private to the owner. Selecting an upload as a draft does not publish it. Upon a successful home save/restore, `/storefront-api/home/image/{uuid}` serves only the image referenced by the **current** homepage row; other UUIDs and former selections return 404. The response is sessionless, `private, no-store`, nosniff and CSP-sandboxed. Disabling the media-library flag prevents new media selection but does not break a previously selected public image; disabling the home-editor flag disables its public endpoint. Files remain outside the public storage symlink. A previously public image cannot be made secret again from anyone who already downloaded or cached a copy.

For unsaved canvas preview, the admin fetches its authenticated private image on the admin origin and transfers bounded image bytes only to the configured, source-and-origin-checked storefront frame. The frame creates and later revokes an in-memory blob URL; private URLs, cookies and tokens are not sent in the message. A failed fetch leaves the form usable and reports a canvas status. The configured storefront origin must be trusted: it receives the selected draft image bytes. Browser framing/cookie policies can still affect login and preview operation.

Migration `2026_11_11_000000_add_home_hero_media_reference` adds nullable references to current content and snapshots; null retains existing bundled-image behavior, and older clients that omit the field preserve the selection. Foreign keys prevent deleting referenced metadata from current or historical revisions. Save/restore refuses missing image files. Rollback drops these references and **loses selections/history associations**; back up the database and media together, and roll application code and schema together. The private library's existing upload limits and EXIF requirements are documented in `FURNITURE-PRIVATE-MEDIA-PREVIEW.md`.

## Validation and limitations

Feature tests cover legacy migration and clients, authorization, invalid/missing images, conflicts, current-only public access, disabling flags, restoration and referenced-media deletion. Node tests cover private preview messaging and stale-response races. A local nested HTTPS browser test with third-party-cookie phaseout covered upload, unsaved blob preview, public save, storefront propagation, restore and unpublishing; a synthetic sample image is retained in the preview library. Existing Vite builds and the Astro prototype static tests pass. Actual Arena frame behavior, host-specific storage, MySQL migration/concurrency and production publication are unverified. Astro's initial static HTML still contains fallback content until hydration; immediate crawler-visible freshness is not solved.

There is no deletion, library search, responsive renditions, rich alt text, media revision replacement, quotas, malware scanning, remote URL import or general page builder. Only the first slide is connected; other slides remain unchanged. User-uploaded backgrounds retain the original hero's decorative empty alt text, so do not use the image to convey information absent from the text. No automatic publication of other private library items occurs.
