# Furniture private media library — experimental foundation

This is an owner-only, feature-flagged private upload/listing slice. It does **not** publish media, provide public image URLs, connect uploads to the hero or canvas, offer edit/delete, or implement the full media library. Woodex Interior and production data are not used. In the synthetic 5176 preview, enable `FURNITURE_MEDIA_LIBRARY_ENABLED=true` and use Website Studio → Media Library. The application default is off.

## Image and security boundary

- Upload through the authenticated owner workspace, CSRF-protected POST and rate limit. Authorization is checked again against the locked current user inside the metadata transaction. Random UUID filenames are generated by the server; neither the uploaded name nor a supplied URL determines a path. Titles are escaped.
- The input must be a decodable PNG or JPEG no larger than 2 MiB, 3000 pixels per side and 4 megapixels. Server upload limits may be lower. MIME is detected from bytes and checked against decoded image type; GIF, SVG, animated PNG and arbitrary files are refused. GD decodes and re-encodes the raster, stripping original metadata and appended contents. Output also has a 12 MiB cap.
- JPEGs require PHP EXIF support; non-default EXIF orientation is rejected instead of silently rotating or stripping orientation. Export such an image upright first. This synthetic preview's PHP has GD but **does not have EXIF**, so it accepts PNG but rejects JPEG with an explanatory error. Availability on Hostinger must be checked separately. Re-encoding strips profiles/metadata and may change colors or compression; this experiment does not preserve originals or make responsive variants.
- Files are stored on the dedicated `furniture_media` local disk under `storage/app/furniture-media`, outside `public` and outside the storage symlink. The preview route is owner-authenticated, private/no-store, nosniff and CSP-sandboxed. The feature flag must remain enabled to view it. There is no public media route. Do not change the storage root to a web-accessible directory.
- Database metadata uses UUIDs and an actor reference. The service removes the newly written file if the database transaction fails, but a process crash or cleanup failure can still leave an orphan. Never delete or migrate files blindly. Back up the database **and** private media together; rollback drops metadata but deliberately does not delete files. Restore and orphan reconciliation, quotas, retention, deletion/reference tracking, malware scanning and production authorization policy remain to be designed.

## Validation and limits

SQLite tests cover flag/owner authorization, private file access and response headers, invalid and animated inputs, dimensions and size, metadata removal, revoked users, and transactional file cleanup. JPEG behavior has an EXIF-enabled test in hosted CI; the local native PHP lacks EXIF. A nested HTTPS browser simulation tested private PNG upload, rendering, anonymous denial and invalid-file rejection; the synthetic test image was removed afterward. Raw tokenless POST returned 419 in the local preview. Actual Arena browser behavior, MySQL concurrency, Hostinger storage, file backups and operational limits have not been verified.

Before any production enablement, review upload security and resource limits on the target PHP build, image orientation/color management, storage permissions and capacity, web-server access controls, backups/restores, cleanup of interrupted uploads, audit/retention policy and handling of hostile images. Do not treat this flag-gated private slice as a completed, public media pipeline.
