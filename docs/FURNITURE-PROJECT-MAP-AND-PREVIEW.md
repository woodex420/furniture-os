## Current preview

- **5174 storefront** opens the actual React storefront. Its development banner links **Open Furniture admin** to `/admin`. The opt-in Vite development proxy forwards `/admin`, `/login`, `/logout`, admin built assets, Livewire and `/storefront-api` to the same synthetic Laravel backend. Browser URLs stay on the storefront origin. Auth, authorization and CSRF remain Laravel's responsibility; the proxy is not for production or public deployment.
- **5176 admin** is a separate synthetic Laravel preview. Its root goes to `/admin` and then `/login` if signed out. This root behavior is explicitly enabled only in the temporary preview using `FURNITURE_ADMIN_PREVIEW_LANDING`; it is false by default. Normal Laravel `/` still returns 503 because Laravel does not yet serve the finished storefront. Nothing here changes production domain routing.
- **5177** is the isolated Astro hero proof, not the complete storefront. Preview credentials are synthetic only; never reuse them outside the preview. Data in the temporary SQLite database may disappear when the sandbox is reset. Saving published content affects this preview, not a live Furniture domain.
- The running backend is a disposable, separately prepared app copy with locked dependencies, synthetic SQLite and preview-only cookie/session settings. Its runtime overrides are not the source configuration. The storefront uses `FURNITURE_PREVIEW_API` only in the Vite **server** process to reach that backend; the internal URL is not shipped to browsers. With no configured backend, the proxy is off and the preview admin link cannot work. Do not set that variable to a real-data service or run this development server as a public admin.
- Browser access and cookies can differ between an embedded Arena frame and direct tabs. If the embedded form fails, use **Open sign-in in a new tab** on the preview login screen. The preview-only cookie probe gives a warning when a test cookie is blocked; it is diagnostic, not proof that the real session is working, and it does not bypass authentication or CSRF. The isolated runtime additionally offers a button to refill the synthetic credentials; this button and values are not part of the production app. Local nested HTTPS simulation covered both entry points, login/logout, Laravel CSS, Blog navigation and Livewire search; the user has reported an actual Arena sign-in problem, whose cause and resolution in their browser are not yet confirmed. No Hostinger deployment was performed.

## Interior reference screenshot — hosting safety note

The supplied Hostinger file-manager screenshot appears to show a repository checkout, `.git` and `.env` inside a `public_html` directory. A screenshot alone does not establish the active domain's document root, whether access is blocked, or whether any secret was exposed. Treat this as a configuration risk requiring a private hosting review: identify the actual document root and site, verify that sensitive paths cannot be served, and prefer placing application/repository files outside the web root with only the application's intended public assets exposed. Avoid downloading, sharing or pasting `.env` contents or credentials. Preserve and back up existing sites before any hosting changes; if a secret is confirmed exposed, rotate it through the provider's secure process. Furniture and Interior are separate; no Hostinger files or Interior data were changed.
