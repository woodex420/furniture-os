# Furniture foundation — owner access and candidate dependency lock

**Status: isolated implementation in progress; not a staging release.** No Hostinger access, real accounts, databases, data imports or deployments were performed. The approved admin design remains an isolated preview; it is not yet integrated into Laravel/Livewire.

## Owner provisioning and access (provisional)

- Added a migration giving users a non-mass-assignable `is_owner` flag defaulting to false, plus a singleton `owner_initializations` table. A transactional `ProvisionFirstOwner` service validates input, normalizes email, hashes the password through Laravel's model cast and refuses an existing installation or a second initialization. The singleton unique key prevents two concurrent callers both committing via this provisioning path. MySQL concurrency, independent user-creation paths, restore and upgrade cases are **not yet proven**.
- Added `furniture:provision-owner` for an explicitly confirmed, **interactive terminal only**. It accepts no password argument, environment variable or pipe; hidden-input fallback is disabled. A local pseudo-terminal test waited for echo to be disabled, then verified that a synthetic password was not echoed and that spaces in that password were preserved in the hash. It is a development candidate, **not an approved Hostinger installation instruction**: Hostinger SSH/TTY, hidden-input behavior, secure initial access and recovery must be separately reviewed. Never put passwords in Git, SQL, chat or release artifacts.
- Defined only `workspace.view`: the initial owner is allowed and ordinary users are denied. There is no implicit owner bypass for other undefined permissions. A non-owner receives 403 for `/admin`; an owner receives the existing 503 placeholder. Other roles, individual capabilities, account disabling, auditing and recovery are still pending. The role policy is provisional until business rules are agreed.

## Candidate Composer lock

The Furniture `composer.lock` was generated by Composer **2.10.1** with PHP **8.4.21**, using a temporary, limited local repository containing package metadata from the reference source's lock (Git blob `d6c1938f946e03ea01a207820510ed8353892c0c`) and BookStack's public lock (Git blob `788c09efbcc74f3e7517385161153857b167c4e2`). This was necessary because Packagist is not reachable from this sandbox. It does **not** copy Interior application code or data. The solver saw only that limited selection, not the full official package catalog. It installed 111 locked packages into a disposable app with `--no-scripts --no-plugins --ignore-platform-req=ext-xmlwriter`.

`composer validate --no-check-publish` passes. All 111 package dist URLs and source URLs refer to the same GitHub repository and same commit reference; this structural check **does not prove the sources or versions safe**, and no successful online Composer security advisory audit was possible. Lock SHA-256 at creation: `84247a4a20e47816ded5bfc204eb8e9950c2667dd901f7fb2eb968f6af3b8ee1`. Review and run `composer audit --locked` against official advisory data before release; do not treat this constrained candidate as a security-approved production lock.

## Evidence

- On temporary native PHP 8.4.21, the entire current Furniture PHPUnit suite ran against the exact candidate-locked third-party dependencies and synthetic SQLite: **17 tests / 152 assertions passed**. The temporary PHP binary lacks `xmlwriter`, so the test used a **modified PHPUnit entry point bypassing its extension check** and Composer installation ignored that single platform requirement. It is therefore **not a standard complete native PHPUnit run**. MySQL's `pdo_mysql` is also absent. A complete runtime must run unmodified PHPUnit, normal Composer install/check-platform-reqs and MySQL tests.
- Pint passed on nine changed PHP files; Composer manifest/lock validation passed. Root preview tests **28/28** and preflight tests **4/4** passed.
- Local HTTP smoke, using the same locked dependency candidate and a disposable SQLite DB: CSRF-less login returned 419, the synthetic owner login reached the intentionally pending `/admin` 503, a synthetic non-owner received 403, and owner logout returned to guest behavior. This was localhost, not hosted HTTPS or browser acceptance; temporary server stopped.
- `.github/workflows/furniture-validation.yml` defines a no-deployment, pinned-action native PHP 8.4/SQLite test and Composer advisory check plus locked frontend build. YAML was parsed locally but it has **not been run on GitHub**; its success, repository Actions permissions and advisory results are unknown. No deployment secrets are used by the workflow.
