# Furniture lead editing — limited preview slice

The owner can edit an existing lead's **title and source** in Customers → Leads → a lead → **Edit title and source**. This is not the complete CRM: status, linked contact, assignment, follow-ups, imports, external intake, deletion and staff access are not implemented by this change. The public storefront is not connected to this editor. No records are created or imported by the migration.

The feature is separately disabled by default (`FURNITURE_LEAD_EDITING_ENABLED=false`). Tracked code requires an authenticated owner and retains Laravel's CSRF protection and request throttling. In the existing 5188 disposable no-login preview it is enabled for synthetic data; anyone with that preview link can read and edit, so do not use sensitive or real data. The preview database was backed up before migration. This open preview bypass is not part of the tracked app and must not be deployed.

The migration adds a non-null revision counter initialized to zero to existing and new leads. Edits compare the submitted revision, update only title/source, increment the revision and insert an actor-attributed `lead.updated` event in the existing audit table in one transaction. No-op saves do not add events. Validation and stale revisions return the attempted values and error directly, without relying on session-flashed form data. To resolve a conflict, copy the attempted changes, reload the current record and apply them deliberately. The event records who changed which lead and when, not before/after values or a recoverable revision history. Every future writer must participate in revision updates; direct SQL or another writer that ignores the revision can undermine conflict detection.

Verification: partial local PHPUnit/SQLite suite passed, including flag/owner permission, validation, escaped input, stale updates, no-op, throttle, revoked ownership and audit failure rollback. Pint passed. A separate disposable test database was used to exercise edit/save and a stale conflict in a nested HTTPS iframe with cookies stripped; no test lead was written to 5188. MySQL row locking, true simultaneous writes, hosting, full audit history and actual Arena browser behavior still need verification. Back up and rehearse migrations and rollback before any real-data use; rollback removes the revision counter. Not a deployment approval.
