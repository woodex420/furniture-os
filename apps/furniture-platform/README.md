# WOODEX Furniture platform — isolated foundation

**Not an installable release. Do not upload or expose this application.** This is an independent Furniture application foundation started from the official `laravel/laravel` 13.x skeleton at commit `a255d7688770af9713daff1439c47ff9bc6abd47`. The source package identifies itself as MIT in `composer.json`. The original skeleton archive SHA-256 is `87f746392b7d8c2f1590a12c4a7317b5823386a40dd69b1007756cfbac21d68f`. No Interior application source, users, databases, assets or configuration were copied into this directory. The earlier Interior-derived application remains in `../laravel-admin-source/` as an isolated reference, not this Furniture runtime.

## Current state

- PHP requirement is `^8.4.1` with Livewire `^4.4`. The Composer lock was produced using constrained offline metadata and then updated for advisories; GitHub validation run `43971341289` passed the standard locked install, PHPUnit and Composer audit for that run's SHA. That is not a complete security review. There is no installed vendor tree in this source. See `../../docs/FURNITURE-OWNER-AND-LOCK-PROGRESS.md`.
- `/` intentionally returns 503 rather than pretending an unfinished storefront is live. `/admin` now renders an in-progress shell based on the approved preview behind session authentication and a provisional owner-only gate. Its Livewire summary shows pending states, not business records; module actions and metrics are not connected. An isolated interactive first-owner provisioning candidate exists, but it is not approved for Hostinger. Registration, other roles, account recovery, real features and permission policies remain pending.
- A minimal session-authentication foundation and feature tests are present. The login form is temporary development markup, not the approved admin design. Laravel's normal web CSRF middleware is retained; sign-in uses per-account/IP and aggregate-IP throttling, successful login rotates the session and logout invalidates it. Workspace/login responses are marked private/no-store and noindex. This is incomplete and **must not be exposed as an operational login**: full authentication/authorization, account lifecycle, rate-limit behavior across hosting, session security, real browser/HTTPS and security review are pending.
- `package-lock.json` covers the Vite/Tailwind assets. The shell reuses styles and icons from the approved standalone dashboard, with unavailable business features marked pending. The local build is not a release artifact, and visual fidelity and accessibility require continued review.
- A later disposable native PHP 8.4.21/SQLite run passed the current 17 tests / 152 assertions with the candidate-locked dependencies and PHPUnit 12.5.38, plus a localhost owner/non-owner CSRF smoke. The temporary PHP lacks `xmlwriter`, so Composer installation ignored that requirement and a modified PHPUnit entry point bypassed its extension check. This is partial experimental evidence, not a standard locked test or security acceptance. See `../../docs/FURNITURE-OWNER-AND-LOCK-PROGRESS.md` for provenance and limits.
- Standard Laravel migrations for users, cache and jobs plus the new owner initialization migration are **not a reviewed Furniture SQL export**. Only disposable local SQLite databases and synthetic accounts were created; no Hostinger database, real accounts, SQL dump, credentials, customer data or live integration were created.

## Before any distribution

Establish a complete native PHP/Composer test environment; review the candidate Composer lock and official advisories; build and test dependencies, auth, permissions and the actual UI; implement the requested business workflows, storefront and Livewire components; and pass synthetic MySQL and security checks. Only then build a versioned ZIP and, if requested, generate a reviewed SQL schema including consistent Laravel migration state from a disposable database. A host-created database name and username are hosting-specific: configure them privately on the server, never in Git, a shared ZIP or chat. See `../../docs/FURNITURE-PACKAGE-AND-MANUAL-DATABASE-PLAN.md`.
